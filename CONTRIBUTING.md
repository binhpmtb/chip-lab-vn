# Contributing

Keep lessons technically correct, beginner-friendly and bilingual. Write original explanations and exercises, citing primary documentation. Preserve existing stable IDs so saved progress remains useful.

Use a branch for each focused change. Explain the intended behavior and validation in the pull request. Run lint, typecheck, format checks, tests and production build before submitting. New engines must remain in terminable browser Workers and include source provenance and required notices.

Exercise changes need a solution that passes and a deliberately incomplete starter that fails. Add boundary vectors for widths, overflow, reset and state transitions. Timing and physical design lessons must distinguish behavioral simulation from physical implementation measurements.

Do not commit credentials, commercial PDKs, private design data or content without reuse permission. Contributions must be compatible with GPL-2.0-or-later and retain third-party notices.
